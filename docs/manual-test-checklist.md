# Manual device checklist

Spec success criterion 7: on the phone, playback continues with the screen locked for at least 30 minutes, the notification controls work, and reopening the app resumes from the saved position (within one segment). Run this after changes to `src/playback/` or `android/.../narrator/`.

**Setup:** `npm run android:apk`, then install `android/app/build/outputs/apk/debug/app-debug.apk` (`adb install -r …`, or copy the file to the phone). Create a story with at least two analysed parts and open the reader.

| #   | Check                                                                  | How                                                                                     | Emulator (2026-10-15)                                                                                                                                     | Phone |
| --- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ----- |
| 1   | Plays with the screen locked for ≥ 30 min                              | Play, lock, pocket the phone for 30 min                                                 | Pass: 33 min with the screen off and deep Doze forced (spike build, ADR-001)                                                                              |       |
| 2   | Moves into the next part by itself while locked                        | Start near the end of a part, lock, wait                                                | Pass: "first half" → "second half" at 11:18 with the screen off and deep Doze forced, no JS involved                                                      |       |
| 3   | Media controls in the notification shade (pause, play, previous, next) | Pull down the shade during playback                                                     | Pass: media card with story and part titles; all four buttons work; the in-app play button follows                                                        |       |
| 4   | Media controls on the lock screen                                      | Lock the phone during playback, wake the screen                                         | Not tested (no screen lock on the emulator). The same media card is what Android shows on the lock screen                                                 |       |
| 5   | Reader highlight follows playback                                      | Watch the reader while playing; skip with the notification                              | Pass: highlight moved with each line and with notification skips                                                                                          |       |
| 6   | Resume after the app is killed (within one segment)                    | Play into a part, force-stop the app (Settings → Apps → Force stop), reopen, press play | Pass: killed at part 2, segment 3; reopened at part 2, segment 3. Also passed with the app's own saved position made stale, using the natively saved line |       |
| 7   | Voices missing on the device are substituted                           | Import a story exported on desktop                                                      | Covered by unit tests (`resolveVoice`, native engine); not run on the device                                                                              |       |
| 8   | Headset / Bluetooth buttons                                            | Press play/pause on wired or Bluetooth headphones                                       | **Fails (known):** Android sends media buttons to the app it sees playing audio, and TTS audio belongs to the TTS engine's process. See ADR-001           |       |
| 9   | Vendor battery saver doesn't stop playback                             | Samsung, Xiaomi and similar: 30 min locked with default battery settings                | Phone only                                                                                                                                                |       |

Record the phone model and Android version with the phone results.
